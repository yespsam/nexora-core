# NEXORA CORE 实体设备云端架构

状态：设计基线，尚未替换当前生产同步
日期：2026-07-30

## 本机验证状态

PostgreSQL 16 迁移、独立 API/维护角色和本机设备 API 已完成。手机、NC-01 项链、桌面三个虚拟设备使用独立 P-256 密钥，在同一保险库中并发写入 1000 条 AES-GCM 密文事件；事件总数、唯一 ID、分设备序号和哈希链一致。重复投递、跨租户隔离、设备撤销、ECDH-ES+A256KW 密钥轮换、HKDF 恢复和账号删除均已通过。该结果只代表单机数据库闭环，不代表测试云、真实网络或实体硬件验收完成。

## 核心决定

首款 NC-01 项链只通过 BLE 连接手机，由手机负责联网、账号恢复、云端同步、AI 请求和家居控制。项链不直接连接公网，不保存长期云端令牌，也不保存完整聊天记录。

当前恢复码加 Netlify Blobs 继续服务网页原型。实体测试前，将人格主数据迁移到 PostgreSQL 只追加事件库；Netlify Blobs 或其他对象存储只保存加密快照和可选媒体。

| 数据 | 项链 | 手机 | PostgreSQL | 对象存储 |

## 同步模型

每次取名、成长、对话、记忆变化和设置修改都生成一个不可修改的加密事件。事件外层只暴露同步所需的假名化元数据：

- 公共保险库 ID，不包含账号或伙伴名字。
- 设备 ID 和单调递增的设备序号。
- 密钥版本、发生时间和上一事件哈希。
- AES-256-GCM 密文。
- ES256 设备签名和签名密钥 ID。

伙伴名字、事件类型、对话内容、长期记忆和人格参数全部位于密文内。服务器验证设备签名、设备未撤销、序号未重复后，以单条事务插入事件。`device_id + device_sequence` 和 `event_id` 同时保证幂等。

客户端按服务器游标拉取事件并在本地解密、排序和合并。每 50 个事件或每 24 小时生成一次加密人格快照；新设备先下载最新快照，再重放之后的事件。

## 密钥层级

1. 手机首次创建 256 位保险库密钥，用于加密人格事件和快照。
2. 恢复密钥只负责包装保险库密钥，恢复码本身永不上传。
3. 每台设备生成独立 ES256 签名密钥和密钥交换密钥。
4. 云端为每台已授权设备保存一份加密后的保险库密钥包。
5. 设备丢失后，手机撤销设备、提升密钥版本，并为剩余设备重新包装新密钥。
6. 云端 KMS 仅保护服务凭证、数据库备份密钥和签名基础设施，不持有用户恢复密钥。

设备撤销只能阻止未来访问，无法擦除失窃设备已经下载的数据。因此项链只保留最小缓存，并必须启用 Flash Encryption、Secure Boot 和签名 OTA。

## AI 隐私边界

端到端加密保护的是静态保存和跨设备同步。只要使用云端语言模型，本次回答所需的文本仍会在受控服务中短暂解密处理，这不能表述为服务器永远看不到明文。

首版执行以下边界：

- 手机选择最多 6 条相关记忆和最近对话，避免上传完整人格库。
- AI 请求不进入普通日志，不记录恢复码、密钥、原始音频或完整保险库。
- 模型回复返回后立即丢弃服务端临时上下文。
- 用户关闭云端智能时，项链仍可执行本地动作、状态同步和预设回应。
- 后续本地小模型成熟后，再把记忆检索和部分推理迁移到手机。

## 数据保留基线

| 数据类别 | 默认保留 |
| --- | --- |
| 加密人格事件 | 账号存续期间，删除申请完成后清除 |
| 加密人格快照 | 保留最近 3 份及每月 1 份灾备快照 |
| 原始语音 | 默认不保存；用户主动开启时最长 24 小时 |
| 家居和电脑命令 | 5 分钟失效，执行记录 7 天后去除内容 |
| 设备安全日志 | 90 天，不包含对话正文 |
| 电量和温度聚合 | 30 天 |
| 删除宽限期 | 7 天可撤销，随后执行密钥销毁和数据清除 |

最终保留期限需要在内测地区、云服务地区和隐私协议确定后由合规律师复核。

## 数据库边界

初始迁移创建以下表：

- `accounts`: 外部认证主体，不直接存放密码。
- `companion_vaults`: 每个伙伴的加密保险库和当前密钥版本。
- `devices`: 手机、项链、桌面和恢复设备的公钥与撤销状态。
- `device_key_envelopes`: 分设备保存的加密保险库密钥。
- `recovery_key_envelopes`: 由用户恢复密钥单独包装的保险库密钥。
- `companion_events`: 只追加的加密人格事件。
- `companion_snapshots`: 对象存储快照索引和完整性哈希。
- `device_commands`: 有失效时间的家居、电脑和设备命令。
- `telemetry_rollups`: 不含对话内容的设备健康聚合。
- `deletion_requests`: 可审计的数据删除流程。

所有用户表启用并强制 PostgreSQL Row-Level Security。API 每个事务必须设置认证后的 `app.owner_id`，数据库默认拒绝没有所有者上下文的访问。事件表只允许查询和插入，普通更新与删除由策略和触发器共同阻止。

## 从当前版本迁移

1. 保持 `/api/sync` 和 `NXR1` 恢复码不变，先部署新数据库但不接用户流量。
2. 手机首次连接新服务时，解密现有 Blob 快照并生成 `migration.snapshot.v1` 事件。
3. 新旧系统双写一周，只读取旧系统，核对事件数量、哈希和恢复结果。
4. 切换为读取事件库，旧 Blob 进入只读状态。
5. 通过两台手机加一台模拟项链的并发、弱网、撤销和恢复测试后，停止旧同步写入。
6. 保留加密旧快照 30 天，确认无恢复问题后删除。

## 实体验收门槛

- 项链不能包含恢复码、个人 API Key 或长期云端访问令牌。
- 设备撤销后，旧设备不能提交事件、拉取新密钥包或接收命令。
- 两台手机同时离线互动后重新联网，所有事件均保留且人格结果一致。
- 删除流程能够清除数据库记录、对象存储密文、备份密钥和设备授权。
- 数据库管理员看到的事件不得出现伙伴名字、对话、记忆或原始音频。
- 固件必须通过 Secure Boot、Flash Encryption、签名 OTA 和回滚测试。
