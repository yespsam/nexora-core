# 自定义 3D 陪伴角色：下一版产品方案

状态：2026-09-26 已实现第一版工作室、生成任务链、桌面加载与可编辑长期记忆。尚未配置 Meshy 服务，真实图片转 3D 未开通；本地完整流程使用明确标记的测试素材验证。

## 产品目标

用户可以上传真人照片、动漫图或原创角色图，创建有自己形象、声音、性格和共同记忆的 3D 陪伴角色。陪伴是主要体验，电脑控制作为可选能力，不作为创建角色的前置步骤。继续保持桌面版免配对、自动创建独立身份的体验。

## 第一版支持范围

- 真人照片：转换为风格化 3D 角色，保留主要外观特征；不承诺照片级还原。头像缺少身体信息时，先提供可修改的全身形象预览。
- 动漫、卡通和原创形象：保留主要配色、发型、服饰与特征；允许上传多张参考图。
- 两类都进入同一个陪伴系统。上传类型、形象风格和角色性格分别设置，不能根据外貌自动推断人格或真实身份。
- 可先使用内置角色等待生成，任务完成后再确认切换。生成失败不影响现有伙伴。

## 用户流程

1. 点击“创建我的伙伴”，选择真人照片或动漫／原创形象。
2. 上传参考图，选择风格；缺少全身信息时补充衣着和体型偏好。
3. 查看并确认形象预览，明确这是生成后的目标外观。
4. 后台生成 3D 模型、骨骼和基础动作，显示阶段、失败原因和可重试入口。
5. 旋转查看模型并预览待机、招手、倾听和说话状态；没有通过动作校验的模型不能标记为可用角色。
6. 设置名字、声音和性格，点击“开始陪伴”。

首次自定义角色生成前说明本次额度或费用。实际价格和耗时待供应商验证后确定；普通聊天与模型生成额度分别计量。

## 陪伴体验

- 文字和语音聊天，角色在倾听、思考、说话时有相应状态。
- 桌面常驻、点击回应、问候、可选择开启的日常关心。
- 记住称呼、偏好、重要日期和用户明确愿意保存的共同经历。
- 用户能查看、编辑和删除记忆；不把模型推测直接当作用户事实。
- 主动互动有安静时段与频率设置，用户可以关闭；不通过内疚或排他性措辞促使用户回来。
- 换外观不清空同一伙伴的记忆；新建另一个伙伴则明确建立独立身份与记忆。
- 原照片默认私有，提供删除入口。上传真人照片时确认拥有使用授权，并明确角色是 AI。

## 当前工程基础与缺口

可复用：`tools/generate_meshy_creatures.py` 等离线生成脚本、`shared/creature-3d-viewer.mjs` 的模型显示与动作播放、现有桌面客户端、自动身份、云端对话和语音接口。

必须新增：

- 用户图片上传与私有存储。以现有自动身份认证请求，服务端确定资产归属，不接受客户端指定其他用户身份。
- 持久化的生成任务与工作队列；API 密钥仅在服务端。任务支持幂等提交、进度查询、重试和额度记录，不能依赖桌面窗口一直打开。
- 图片预处理与预览确认、模型生成、骨骼／动作处理、模型体积与动画校验、发布和本地缓存。
- 动态角色资源清单。当前渲染器按内置 starter/stage 查找模型，需扩展为每位用户自己的模型和动作资源。
- 桌面角色管理与下载进度。切换先下载并验证新资源，失败保留旧角色；重启后恢复上次选择。
- 桌面长期记忆。当前 Windows 客户端只保留最近 12 条消息、请求附带最近 10 条，且发送空的长期记忆列表；不能将现状描述为已经具备长期陪伴记忆。

建议任务状态：uploaded → preparing → awaiting_preview_confirmation → generating → rigging → animating → validating → ready。每个处理阶段可进入 failed 或 canceled；ready 只在资源下载和运行校验完成后设置。

## 实施顺序

1. 打通两类图片的上传、形象预览和后台生成任务，用样本验证外观与动作质量。
2. 将自定义角色接入 Mac 和 Windows 桌面、文字对话及语音状态。
3. 补齐可管理的长期记忆、性格一致性和用户选择开启的日常互动。

## 验收条件

- 新用户无需配对码即可创建伙伴；两类图片各完成端到端验证。
- 生成任务关闭窗口后仍可恢复，重复请求不会重复生成或扣减额度。
- 用户之间不能读取原图、生成进度或私有角色资源。
- 失败或不合格模型有明确恢复路径，不覆盖当前角色。
- 新角色可在 Mac 和 Windows 展示并完成对话，重启后保持形象与身份。
- 长期记忆在重启后可用，并可以查看、更正和删除。

本方案不代表已经接通面向用户的图片生成服务；模型服务、成本和处理时间需在实现时实测确认。
